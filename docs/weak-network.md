# 弱网连接与刷新

面板先通过 HTTP polling 建立连接，再尝试升级 WebSocket。代理不支持升级时继续使用 polling。
Socket.IO 的连接尝试不使用会触发 NiceGUI 整页刷新的 manager timeout；单次 HTTP 请求超时为 45 秒，失败后以带随机退避的方式重连。

HTTP 压缩统一交给 NiceGUI 的 GZipMiddleware，关闭 Engine.IO 自己的第二层压缩。当前安装的 Engine.IO ASGI 响应会保留大写的 Content-Encoding，而外层中间件按小写查找；重复压缩会让部分代理解码后仍得到 gzip 字节，导致连接消息解析失败。

服务端心跳间隔为 25 秒，响应超时为 45 秒。断开后页面实例默认保留 300 秒，并保留最多 2000 条待确认消息供恢复。心跳与页面保留时间分别设置，避免延长保留时间后心跳超过代理的空闲限制。

保留新连接的握手状态：旧 transport 延迟报告断开时，只要同一页面仍有另一条有效连接，就不把页面标为离线。这避免 NiceGUI 3.13 中“网络已恢复、但事件被静默忽略”的重叠连接问题。

短时断网时，当前页面及已经加载的输出仍可滚动、选择和复制。连接提示会明确标记内容尚未更新；启动、停止、编辑和导航等需要服务端的操作暂停，离线操作不会排队到恢复后执行。连接恢复并完成握手后原页继续工作。服务重启、页面被关闭或超过保留期限可能需要重新加载；这不是完整的离线应用。

后台刷新默认每 30 秒核实资源与状态，每 10 秒采集当前任务输出；手动刷新仍可使用。已断连、隐藏的浏览器标签页和隐藏项目面板暂停周期采集，不补发错过的刷新。已经开始的训练操作不因此取消。

运行列表和配置字段在原位置更新。相同内容不重复发送；概况输出最多 6 行 / 4 KiB，打开输出页后最多 300 行 / 24 KiB。日志窗口限制不改变远端训练日志，完整日志仍位于启动信息中的远端路径。

可通过服务环境配置调整：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `GPU_SSH_PANEL_RECONNECT_SECONDS` | `300` | 断开后页面保留时间，最低 60 秒 |
| `GPU_SSH_PANEL_REFRESH_SECONDS` | `30` | 资源及任务状态刷新秒数 |
| `GPU_SSH_PANEL_RUN_OUTPUT_SECONDS` | `10` | 当前任务输出刷新秒数 |

相关设计依据：[Socket.IO 连接与 transport 配置](https://socket.io/docs/v4/client-options/)。实际行为同时按当前安装的 NiceGUI 源码、Engine.IO 握手响应及本仓库的连接测试核对。
